# 0023: Revise Codex Child-Agent Disablement

Status: Accepted

Date: 2026-08-12

Owners:

- Product owner and Root Orchestrator

Supersedes:

- [Decision 0022](0022-adopt-codex-hook-prompt-injection.md) only where it names
  `[agents] enabled = false` as the per-manifest nested-delegation control. Exact role
  names, hook matchers, prompt binding, sandbox boundaries, guarded delivery, supported
  Codex baseline, and portable fallback remain current.

Superseded by:

- None

## Context

Codex 0.144.1 reproduced four startup errors for the source manifests. In that parser,
the standalone file's `[agents]` table treats `enabled = false` as a named agent role
and tries to deserialize the boolean as an `AgentRoleToml`, so Codex ignores the entire
custom-agent definition. The current Codex configuration contract also exposes the
stable `features.multi_agent` flag, which disables the collaboration tools controlled
by the same feature.

This is provider schema drift caught by Decision 0022's review trigger. Deleting the
mechanical control would silence the parser but would leave nested delegation guarded
only by instructions.

## Decision

- Revise all four standalone custom-agent layers to set
  `features.multi_agent = false`.
- Keep the existing developer-instruction prohibition as defense in depth.
- Keep Codex 0.147.0 as the tested exact-dispatch baseline; accepting the older parser
  does not claim that older releases implement exact custom-agent selection or hooks.
- Assert the feature flag in the package-owned generated bytes and reject a regression
  back to an `[agents]` table in standalone manifests.

## Options Considered

| Option | Benefits | Costs And Risks | Disposition |
| --- | --- | --- | --- |
| Remove the invalid table only | Stops warnings | Restores nested-agent tools and weakens the authority boundary | Rejected |
| Require a local Codex update without changing manifests | Keeps the original bytes | Leaves avoidable startup noise and whole-manifest rejection on an available parser | Rejected |
| Use `features.multi_agent = false` in each custom layer | Schema-valid on the reproduced parser and preserves mechanical tool removal | Feature behavior remains provider-version-coupled | Revised |

## Consequences

- Source and installed-client manifests no longer collide with the older
  `AgentRoleToml` table shape.
- Nested delegation remains disabled mechanically and prohibited semantically.
- Exact profile selection and lifecycle injection remain supported only on versions
  published by `meta hook --version`.

## Compatibility And Rollback

- The package integration format remains version 1 because the owned file inventory,
  markers, role names, and semantic boundary are unchanged.
- Reverting the generator, four source manifests, tests, and documentation restores the
  prior exact bytes, but also restores the reproduced warnings on Codex 0.144.1.

## Confidence

Confidence: High for the reproduced parser repair and static nested-delegation control;
Medium for future provider compatibility.

## Review Trigger

Revisit when Codex removes or changes `features.multi_agent`, changes standalone custom
agent layering, or exposes a narrower per-agent tool-deny mechanism.
